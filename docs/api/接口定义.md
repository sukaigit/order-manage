# 订单管理系统 API 接口定义

> Phase 2 ② 输出。覆盖 `openspec/specs/` 全部 14 个 spec、共 78 条 REQ。
> 字段命名：**snake_case**，与 `sql/init.sql` 列名保持一致，前端无需字段映射。

## 通用约定

- **Base URL**: `/api`
- **认证**: 登录成功返回 `token`，后续所有请求（除登录、验证码外）必须携带请求头 `Authorization: Bearer <token>`；缺失或失效返回 HTTP 401。
- **命名**: 请求参数、JSON 字段一律 `snake_case`（如 `supplier_id`、`order_no`、`create_time`）；枚举值使用中文字面量（与原型/DB 默认值一致，如 `待审核`、`启用`）。
- **分页请求参数**:
  - `page`：页码，从 1 起，默认 `1`
  - `pageSize`：每页条数，默认 `10`（操作日志默认 `5`，仅支持 5/10/20/50 四档）
- **分页响应**: `data` 固定为 `{ "total": <int>, "list": [ ... ] }`，全局唯一结构，`total` 为满足筛选条件的总条数。
- **统一响应体**（导出类接口除外，其直接返回文件流）:

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

  - 成功：`code = 200`，`data` 为业务数据（分页接口 `data = { total, list }`，无数据操作 `data = null`）。
  - 失败：HTTP 状态码与业务 `code` 对齐（如 401/403/404/400），`message` 为可直接展示给用户的中文提示，`data = null`。详见「状态码与错误码」。
- **时间格式**: `yyyy-MM-dd HH:mm:ss`（如 `2026-01-01 00:00:00`）；筛选类日期参数为 `yyyy-MM-dd`（`start_date`/`end_date`/`date`），与原型 `<input type="date">` 一致，按 `create_time` 日期部分闭区间匹配。
- **权限模型**: 接口级权限 = 登录态 + 角色功能权限（`tb_role_function` 的 `域:操作` 标识）+ 菜单权限（`tb_role_menu`），与 `docs/architecture/architecture.md` RBAC 矩阵一致；无权限返回 HTTP 403。
- **导出接口**: 返回文件流，`Content-Type: application/vnd.ms-excel`，`Content-Disposition: attachment; filename=xxx_yyyy-MM-dd.xls`，内容为 Excel `.xls`；筛选参数与对应列表接口完全一致。

## 一、认证 auth

### 1.1 获取验证码 GET /api/auth/captcha

- **请求**: 无参数
- **响应** `data`:

```json
{
  "captcha_id": "cap_9f3a1c2e",
  "image": "data:image/png;base64,iVBORw0KGgo..."
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| captcha_id | string | — | 验证码会话ID，登录时回传 |
| image | string | — | 4 位图形验证码图片（base64） |

- **权限**: 公开
- **对应 REQ**: REQ-AUTH-002（点击刷新=重新请求本接口）

### 1.2 登录 POST /api/auth/login

- **请求** JSON 体:

| 字段 | 类型 | 必填 | 校验 | 示例 |
|---|---|---|---|---|
| username | string | 是 | 非空；缺失返回「请输入用户名和密码」 | `admin` |
| password | string | 是 | 非空；同上 | `Uu888888!` |
| captcha | string | 是 | 非空（「请输入验证码」）；4位，不区分大小写（「验证码错误」） | `A3K9` |
| captcha_id | string | 是 | 来自 1.1 | `cap_9f3a1c2e` |

- **响应** `data`:

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "first_login": false,
  "user": {
    "id": 1,
    "username": "admin",
    "real_name": "管理员",
    "status": "启用",
    "department_id": 1,
    "department_name": "总部",
    "organization_id": 1,
    "organization_name": "总行",
    "role_id": 1,
    "role_code": "ROLE_ADMIN",
    "role_name": "管理员"
  },
  "menus": [
    {
      "id": 1, "code": "MENU_WORKBENCH", "name": "工作台", "route": "/workbench",
      "menu_type": "level1", "parent_id": null, "sort": 1, "children": []
    }
  ],
  "permissions": ["order:query", "order:create", "audit:pass", "log:view"]
}
```

- **失败业务码**（HTTP 401，`message` 直接展示）:
  - 「用户名或密码错误」（用户名不存在或密码不匹配，并含剩余机会提示逻辑：密码错误且未满5次返回「密码错误，还剩 N 次机会」）
  - 「验证码错误」
  - 「账户已禁用，请联系系统管理员启用」（`status != 启用`）
  - 「账户已锁定；密码错误次数过多，请联系系统管理员解锁」（连续 5 次密码错误，响应含 `locked: true`）
- **业务规则**: 登录成功重置密码错误计数；`first_login=true` 时前端跳转 `/force-password?force=true`；初始化仅 `admin` 可登录。
- **权限**: 公开
- **对应 REQ**: REQ-AUTH-001、REQ-AUTH-002、REQ-AUTH-003、REQ-AUTH-004、REQ-AUTH-008

### 1.3 获取当前用户 GET /api/auth/me

- **请求**: 仅需 `Authorization` 头
- **响应** `data`: 同登录响应（去掉 `token`）的 `user` + `menus` + `permissions`（会话续期/刷新页面恢复状态用）
- **权限**: 登录用户
- **对应 REQ**: REQ-AUTH-001、REQ-ROLE-006（按角色返回可见菜单与功能权限）

### 1.4 退出登录 POST /api/auth/logout

- **请求**: 无 JSON 体；`Authorization` 头携带当前 token
- **响应** `data`: `null`
- **业务规则**: 服务端立即使 token 失效；退出后原 token 请求返回 401，前端清除本地 token 并回 `/login`。
- **权限**: 登录用户
- **对应 REQ**: REQ-AUTH-005

### 1.5 修改密码（普通） PUT /api/auth/password

- **请求** JSON 体:

| 字段 | 类型 | 必填 | 校验 | 示例 |
|---|---|---|---|---|
| old_password | string | 是 | 非空（「请输入当前密码」）；须匹配当前密码 | `Uu888888!` |
| new_password | string | 是 | 非空（「请填写新密码」）；8-20 位且含大写/小写/数字/特殊字符至少 3 种（「密码不符合安全规则」）；不得与 old_password 相同（「新密码不能与当前密码相同」） | `NewPass@2026` |
| confirm_password | string | 是 | 须等于 new_password（「两次密码不一致」） | `NewPass@2026` |

- **响应** `data`: `null`（前端提示「密码修改成功」并清空表单）
- **权限**: 登录用户
- **对应 REQ**: REQ-AUTH-006

### 1.6 修改密码（首次强制） PUT /api/auth/password/force

- **请求** JSON 体:

| 字段 | 类型 | 必填 | 校验 | 示例 |
|---|---|---|---|---|
| new_password | string | 是 | 同 1.5 规则；无「新旧不同」校验 | `NewPass@2026` |
| confirm_password | string | 是 | 须等于 new_password | `NewPass@2026` |

- **响应** `data`: `null`（前端提示「密码修改成功，请重新登录」，1.5s 后跳转 `/login`；服务端同时清除当前 token、`first_login` 置 false）
- **权限**: 登录用户（`first_login=true` 或强制模式会话）
- **对应 REQ**: REQ-AUTH-007

## 二、工作台 workbench

### 2.1 统计 GET /api/workbench/stats

- **请求**: 仅需 `Authorization` 头
- **响应** `data`:

```json
{
  "total_orders": 128,
  "pending_orders": 12,
  "done_orders": 96,
  "rejected_orders": 7,
  "active_suppliers": 2,
  "welcome": {
    "title": "欢迎使用订单管理系统",
    "pending_count": 12,
    "rejected_count": 7,
    "tips": "可前往「订单管理」维护订单，「订单审核」处理审核，「统计报表」查看经营分析。"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| total_orders | int | 全部订单数 |
| pending_orders | int | 状态=待审核 订单数（与 welcome.pending_count 一致） |
| done_orders | int | 状态=已完成 订单数 |
| rejected_orders | int | 状态=已驳回 订单数（welcome.rejected_count 同值） |
| active_suppliers | int | 状态=启用 供应商数 |
| welcome | object | 欢迎卡片文案与待办数 |

- **业务规则**: 统计随订单/供应商数据变化实时重算（实时 COUNT 查询，不缓存）。
- **权限**: 登录用户且角色拥有「工作台」菜单（内置三角色均有）
- **对应 REQ**: REQ-WB-001、REQ-WB-002、REQ-WB-003

## 三、订单 orders

### 3.1 订单列表 GET /api/orders

- **请求** Query 参数:

| 参数 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| keyword | string | 否 | 订单编号/名称模糊搜索（不区分大小写） | `ORD2026` |
| supplier_id | int | 否 | 供应商筛选（下拉，传 id） | `1` |
| status | string | 否 | 状态枚举：`待审核`/`已驳回`/`已完成` | `待审核` |
| start_date | string | 否 | 创建时间起，`yyyy-MM-dd`，含当日 | `2026-01-01` |
| end_date | string | 否 | 创建时间止，`yyyy-MM-dd`，含当日 | `2026-12-31` |
| page | int | 否 | 默认 1 | `1` |
| pageSize | int | 否 | 默认 10 | `10` |

- **响应** `data`:

```json
{
  "total": 42,
  "list": [
    {
      "id": 1,
      "order_no": "ORD2026010101",
      "name": "华东原料采购单",
      "amount": 12500.00,
      "supplier_id": 1,
      "supplier_name": "华东原料供应商",
      "status": "待审核",
      "remark": "季度补货",
      "create_time": "2026-01-01 09:00:00",
      "update_time": "2026-01-01 09:00:00"
    }
  ]
}
```

- **业务规则**: 多条件为「与」关系；翻页保持筛选条件。
- **权限**: 登录用户且具备 `order:query`（管理员/审核员/普通用户）
- **对应 REQ**: REQ-ORDER-001

### 3.2 新增订单 POST /api/orders

- **请求** JSON 体:

| 字段 | 类型 | 必填 | 校验 | 示例 |
|---|---|---|---|---|
| order_no | string | 是 | 非空；全局唯一（重复返回 409） | `ORD2026010101` |
| name | string | 是 | 非空 | `华东原料采购单` |
| amount | number | 是 | 非空；≥ 0（负数返回「金额不能为负数」） | `12500.00` |
| supplier_id | int | 是 | 非空；须存在且 `status=启用`（停用供应商不可选） | `1` |
| remark | string | 否 | 可选 | `季度补货` |

- **响应** `data`: 完整订单对象（同 3.1 列表项）；`status` 固定为 `待审核`，`create_time` 为当前时间，服务端生成。
- **权限**: 具备 `order:create`（管理员/普通用户）
- **对应 REQ**: REQ-ORDER-002、REQ-SUP-005（仅启用供应商可选）

### 3.3 编辑订单 PUT /api/orders/{id}

- **路径参数**: `id` — 订单 ID（int）
- **请求** JSON 体: 同 3.2（`order_no` 不可修改，传入忽略；`status` 由服务端流转）
- **响应** `data`: 更新后的完整订单对象
- **业务规则**:
  - 仅 `待审核`/`已驳回` 状态可编辑；`已完成` 返回 HTTP 422「已完成订单不可编辑」
  - 原状态为 `已驳回` 且保存成功 → `status` 自动回到 `待审核`
  - `amount < 0` 返回 HTTP 400「金额不能为负数」
- **权限**: 具备 `order:update`（管理员/普通用户）
- **对应 REQ**: REQ-ORDER-003

### 3.4 删除订单 DELETE /api/orders/{id}

- **路径参数**: `id` — 订单 ID
- **请求**: 无 JSON 体（二次确认由前端完成）
- **响应** `data`: `null`
- **业务规则**: 仅 `待审核`/`已驳回` 可删；`已完成` 返回 HTTP 422「已完成订单不可删除」；订单不存在返回 404。
- **权限**: 具备 `order:delete`（管理员/普通用户）
- **对应 REQ**: REQ-ORDER-004

### 3.5 订单详情 GET /api/orders/{id}

- **路径参数**: `id` — 订单 ID
- **响应** `data`: 完整订单对象（同 3.1 列表项单条）；订单不存在返回 HTTP 404。
- **权限**: 具备 `order:query`
- **对应 REQ**: REQ-ORDER-005

### 3.6 订单导出 GET /api/orders/export

- **请求**: Query 参数与 3.1 完全一致（不含 page/pageSize，导出全部匹配数据）
- **响应**: 文件流 `.xls`，表头：订单编号、订单名称、金额、供应商、状态、创建时间、备注
- **业务规则**: 带筛选仅导出匹配数据；无筛选导出全部。

## 四、订单审核 order-audit

> **选型说明**：审核列表采用**专用接口 `GET /api/order-audits`**，不复用 `GET /api/orders?status=待审核`。理由：原型审核列表包含「审核人/审核时间/审核意见」三列（订单表无这些字段，需联查 `tb_order_audit` 最新记录），且审核列表默认筛选为 `status=待审核` 并带独立「待审核 N 单」计数；专用接口一次返回全部展示字段，避免前端二次请求拼装。

### 4.1 审核列表 GET /api/order-audits

- **请求** Query 参数:

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| keyword | string | 否 | 订单编号/名称模糊搜索 |
| status | string | 否 | `待审核`/`已驳回`/`已完成`，前端默认传 `待审核` |
| page / pageSize | int | 否 | 同通用约定 |

- **响应** `data`:

```json
{
  "total": 12,
  "list": [
    {
      "id": 1,
      "order_no": "ORD2026010101",
      "name": "华东原料采购单",
      "amount": 12500.00,
      "supplier_id": 1,
      "supplier_name": "华东原料供应商",
      "status": "待审核",
      "create_time": "2026-01-01 09:00:00",
      "auditor": "审核员",
      "audit_time": "2026-01-02 10:00:00",

      "pending_count": 12
    }

```

- **说明**: `auditor`/`audit_time`/`opinion` 取该订单最新一条 `tb_order_audit` 记录，无记录时为 `null`；`pending_count` 为当前待审核总数（列表页角标）。

### 4.2 审核通过 POST /api/order-audits/{id}/pass

- **路径参数**: `id` — 订单 ID
- **请求** JSON 体:

| 字段 | 类型 | 必填 | 校验 | 示例 |
|---|---|---|---|---|
| opinion | string | 否 | 审核意见，通过时可为空 | `""` |

- **响应** `data`: `{ "order_id": 1, "status": "已完成", "audit": { "result": "通过", "auditor": "审核员", "opinion": "", "audit_time": "2026-01-03 14:00:00" } }`
- **业务规则**:
  - 订单必须为 `待审核`，否则 HTTP 422「仅待审核订单可审核」
  - 通过后订单 `status` 直接变为 `已完成`（不经「已审核」中间态），写入 `tb_order_audit`
  - 审核人取当前登录用户
- **权限**: 具备 `audit:pass`（管理员拥有全部功能；按 RBAC 矩阵业务上仅审核员执行审核操作，非审核员角色执行返回 403）
- **对应 REQ**: REQ-AUDIT-001、REQ-AUDIT-002、REQ-AUDIT-004、REQ-AUDIT-005

### 4.3 审核驳回 POST /api/order-audits/{id}/reject

- **路径参数**: `id` — 订单 ID
- **请求** JSON 体:

| 字段 | 类型 | 必填 | 校验 | 示例 |
|---|---|---|---|---|
| opinion | string | 是 | 非空（「驳回时审核意见必填」），≤255 字符 | `金额与合同不符，请修改后重新提交` |

- **响应** `data`: `{ "order_id": 1, "status": "已驳回", "audit": { "result": "驳回", "auditor": "审核员", "opinion": "金额与合同不符…", "audit_time": "2026-01-03 14:05:00" } }`
- **业务规则**: 订单须为 `待审核`（否则 422）；驳回后 `status=已驳回` 并记录驳回原因；已驳回订单经 3.3 编辑保存后自动回 `待审核`，可再次审核。
- **权限**: 具备 `audit:reject`（同 4.2，仅审核员实际执行）
- **对应 REQ**: REQ-AUDIT-001、REQ-AUDIT-003、REQ-AUDIT-004、REQ-AUDIT-005

## 状态码与错误码

HTTP 状态码与响应体 `code` 保持同值；`message` 为面向用户的中文提示。

### HTTP 状态 + 业务码总表

| HTTP | 业务 code | 含义 | 触发示例 |
|---|---|---|---|
| 200 | 200 | 成功 | 查询/新增/修改/删除成功 |
| 400 | 400 | 参数校验失败 | 必填缺失、格式非法、金额为负、分页参数非法、两次密码不一致、密码不符合安全规则 |
| 401 | 401 | 未认证 | 未携带/携带失效 token；登录接口凭据错误、验证码错误、账户锁定/禁用（登录场景下带具体 message） |
| 403 | 403 | 无权限 | 非审核员执行审核、非管理员访问报表/系统管理/日志、角色无 `域:操作` 功能权限 |
| 404 | 404 | 资源不存在 | `GET /api/orders/{id}` 不存在；用户/供应商/部门/机构/菜单/功能 ID 不存在 |
| 409 | 409 | 唯一性冲突 | 订单编号、供应商编号、用户名、部门编号、角色编号、菜单编号、权限标识重复 |
| 422 | 422 | 业务规则拒绝 | 见下表 |
