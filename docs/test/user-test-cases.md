## UT-AUTH-01 登录与验证码
- **对应 TC**: TC-AUTH-P-01/P-02/N-01/N-02/N-03/N-04 · **结果**: ⏳
- 步骤:
  1. 打开 `/login`，观察验证码图片加载
  2. 不填任何字段点登录
  3. 输入 admin + 错误密码 + 正确验证码，登录
  4. 输入 admin/123456 + 错误验证码，登录
  5. 点击验证码图片，观察是否刷新
  6. 输入 admin/123456 + 正确验证码（注意大小写字母），登录
- 预期: 1→图可见；2→「请输入用户名和密码」；3→「用户名或密码错误」；4→「验证码错误」；5→图片刷新（新 id）；6→登录成功跳转 `/workbench`（大小写不敏感，覆盖 TC-AUTH-B-03）

## UT-AUTH-03 首次登录强制改密
- **对应 TC**: TC-AUTH-P-04/P-08 · **结果**: ⏳
- 步骤:
  1. 用重置后的账号登录（first_login=true）
  2. 在 `/force-password` 输入弱密码 → 强密码两次一致 → 提交
  3. 用旧标签页任意操作；用新密码重新登录
- 预期: 1→跳转 `/force-password` 且不可进工作台；2→弱密码报「密码不符合安全规则」，不一致报「两次密码不一致」，成功提示并跳登录；3→旧会话失效（401），新密码登录成功且不再强制改密

## UT-AUDIT-01 审核闭环（驳回→编辑→通过）
- **对应 TC**: TC-AUDIT-P-04/P-05/P-07/N-02/N-05/N-06 · **结果**: ⏳
- 步骤:
  1. 审核员登录 → 订单审核 → 对待审核单选「驳回」，意见留空提交；填 >255 字提交；填合法意见提交
  2. 对已驳回单「编辑」保存 → 回到审核列表
  3. 对回待审核的单「通过」→ 查看详情与审核历史
  4. 换 admin 登录执行通过；换普通角色执行通过
- 预期: 1→400「驳回时审核意见必填」/400 长度超限/成功变已驳回；2→状态回「待审核」；3→变已完成，历史 2 条升序（驳回、通过）含意见与审核人；4→admin 403、普通角色 403（仅审核员可审）
