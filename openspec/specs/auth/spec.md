## Purpose

认证模块提供系统登录、退出与密码维护能力，涵盖登录校验（用户名/密码/验证码）、密码错误锁定、账户状态拦截、退出登录、修改密码（普通模式与首次登录强制模式）等功能，并约束系统初始化仅预置默认管理员账号 admin 可用于登录。密码规则统一为：8-20 位，且包含大写字母、小写字母、数字、特殊字符中至少 3 种。

## Requirements

### REQ-AUTH-001: 登录

系统 SHALL 提供登录页，用户须输入用户名、密码与验证码方可登录；用户名、密码缺失 MUST 被拒绝并提示「请输入用户名和密码」；登录成功且非首次登录时 MUST 跳转至工作台（/workbench）；用户名不存在或密码不匹配 MUST 返回「用户名或密码错误」，并清空密码与验证码、刷新验证码。

#### Scenario: 校验通过登录成功进入工作台

- WHEN 用户输入存在的用户名、正确密码与正确验证码并点击登录
- THEN 系统登录成功并跳转至工作台页面

#### Scenario: 用户名或密码错误被拒绝

- WHEN 用户输入的用户名不存在或密码不匹配
- THEN 系统拒绝登录并返回「用户名或密码错误」，清空密码与验证码输入并刷新验证码

#### Scenario: 必填项缺失被拒绝

- WHEN 用户未输入用户名或密码即点击登录
- THEN 系统拒绝登录并提示「请输入用户名和密码」

#### Scenario: 首次登录跳转强制改密

- WHEN 首次登录（firstLogin）的用户输入正确凭据登录成功
- THEN 系统跳转至强制修改密码页（/force-password?force=true）而非工作台

### REQ-AUTH-002: 验证码

系统 SHALL 在登录页提供 4 位图形验证码；验证码 MUST 不区分大小写校验；验证码缺失 MUST 提示「请输入验证码」；验证码错误 MUST 提示「验证码错误」并清空输入、刷新验证码；点击验证码图片 MUST 刷新验证码。

#### Scenario: 验证码正确通过校验

- WHEN 用户输入与图形验证码一致的字符（忽略大小写）
- THEN 验证码校验通过，继续执行用户名与密码校验

#### Scenario: 验证码错误被拒绝并自动刷新

- WHEN 用户输入与图形验证码不一致的字符
- THEN 系统提示「验证码错误」，清空验证码输入并生成新的验证码

#### Scenario: 点击验证码刷新

- WHEN 用户点击验证码图片
- THEN 系统重新生成并渲染一个新的验证码

### REQ-AUTH-003: 密码错误锁定

系统 SHALL 统计用户密码连续错误次数；累计 5 次密码错误后账户 MUST 被锁定，登录页 MUST 展示「账户已锁定」及「密码错误次数过多，请联系系统管理员解锁」提示，且锁定期间输入框与登录按钮 MUST 不可用；未达 5 次时 MUST 提示剩余机会次数；登录成功 MUST 重置错误计数。

#### Scenario: 密码错误提示剩余次数

- WHEN 用户密码错误且累计错误次数未达 5 次
- THEN 系统提示「密码错误，还剩 N 次机会」，并清空密码与验证码、刷新验证码

#### Scenario: 连续 5 次密码错误账户锁定

- WHEN 用户累计 5 次输入错误密码
- THEN 账户被锁定，登录页展示锁定提示，用户名、密码、验证码输入框与登录按钮均不可用

#### Scenario: 登录成功重置错误计数

- WHEN 用户登录成功
- THEN 该用户的密码错误累计次数重置为 0

### REQ-AUTH-004: 账户状态（停用）

状态为「停用」（非启用）的账户 MUST 无法登录，系统 MUST 返回「账户已禁用，请联系系统管理员启用」，并清空密码与验证码、刷新验证码。

#### Scenario: 停用账户登录被拒绝

- WHEN 状态为「停用」的用户输入正确凭据尝试登录
- THEN 系统拒绝登录并提示「账户已禁用，请联系系统管理员启用」，该账户不会进入系统

### REQ-AUTH-005: 退出登录

系统 SHALL 在顶部导航的用户菜单中提供「退出登录」入口；执行退出登录后 MUST 返回登录页（/login），且退出后原页面不再可通过浏览器前进等方式继续操作（需重新登录）。

#### Scenario: 退出登录返回登录页

- WHEN 用户点击顶部用户菜单中的「退出登录」
- THEN 系统结束当前会话并跳转回登录页

#### Scenario: 用户菜单同时提供修改密码入口

- WHEN 用户点击顶部用户菜单中的「修改密码」
- THEN 系统跳转至修改密码页（/change-password）

### REQ-AUTH-006: 修改密码

系统 SHALL 提供普通模式修改密码（系统内，需输入当前密码）：当前密码 MUST 必填；新密码 MUST 满足 8-20 位且含大写字母、小写字母、数字、特殊字符中至少 3 种；新密码 MUST 与当前密码不同；确认密码 MUST 与新密码一致；校验失败 MUST 以警告提示对应错误；校验通过 MUST 提示「密码修改成功」并清空表单。

#### Scenario: 修改成功提示

- WHEN 用户输入正确的当前密码、符合规则且与当前密码不同的新密码，且两次输入一致
- THEN 系统提示「密码修改成功」，表单清空

#### Scenario: 当前密码缺失被拒绝

- WHEN 普通模式下用户未输入当前密码即提交
- THEN 系统提示「请输入当前密码」并拒绝提交

#### Scenario: 新密码不符合安全规则被拒绝

- WHEN 用户提交的新密码不满足 8-20 位或字符种类少于 3 种
- THEN 系统提示「密码不符合安全规则」并拒绝提交；保存按钮在新密码不合规时 MUST 禁用

#### Scenario: 两次密码不一致被拒绝

- WHEN 用户提交的确认密码与新密码不一致
- THEN 系统提示「两次密码不一致」并拒绝提交

#### Scenario: 新密码与当前密码相同被拒绝

- WHEN 普通模式下用户提交的新密码与当前密码相同
- THEN 系统提示「新密码不能与当前密码相同」并拒绝提交

### REQ-AUTH-007: 首次登录强制改密

系统 SHALL 提供首次登录强制修改密码页（/force-password，或 /change-password?force=true）：该模式 MUST 不要求输入当前密码；页面 MUST 提示「首次登录，请修改密码」；校验规则与普通模式一致（必填、8-20 位且至少 3 种字符、两次一致，但无「新旧不同」校验）；修改成功 MUST 提示「密码修改成功，请重新登录」，并在 1.5 秒后自动跳转登录页（/login）。

#### Scenario: 强制改密成功后跳转登录页

- WHEN 首次登录用户在强制模式下提交符合规则且两次一致的新密码
- THEN 系统提示「密码修改成功，请重新登录」，约 1.5 秒后自动跳转至登录页

#### Scenario: 强制模式无需当前密码

- WHEN 用户在强制模式（force=true 或 /force-password）下提交修改且未填写当前密码
- THEN 系统不因缺少当前密码而拒绝，仅校验新密码规则与一致性

#### Scenario: 强制模式必填与规则校验

- WHEN 强制模式下用户未填写新密码/确认密码，或新密码不符合规则，或两次不一致
- THEN 系统分别提示「请填写新密码」「密码不符合安全规则」「两次密码不一致」并拒绝提交

### REQ-AUTH-008: 预置用户仅 admin

系统初始化 MUST 仅预置默认管理员账号 admin（用户名 admin、角色「管理员」、状态「启用」）用于登录；其余账号 MUST 由管理员通过用户管理模块创建后方可登录。原型内置登录用户列表 MUST 仅包含 admin 一个账号。

#### Scenario: 初始化后仅 admin 可登录

- WHEN 系统完成初始化
- THEN 仅用户名 admin 的账号存在于登录用户列表中，其他用户名登录一律返回「用户名或密码错误」

#### Scenario: admin 凭据正确可登录

- WHEN 用户以 admin 及其正确密码（配合正确验证码）登录
- THEN 系统登录成功并按首次登录标记决定跳转强制改密页或工作台
